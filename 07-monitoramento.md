# 7.1 Velocity

<!-- O que é velocity para este time e como será medida (SP/sprint, horas/sprint) -->

A **Velocity** representa a quantidade de trabalho que a equipe consegue concluir durante um Sprint.

No Agenda Sport, a Velocity será medida através da quantidade de **Story Points (SP)** concluídos ao final de cada Sprint. Cada tarefa será estimada pela equipe antes do início do Sprint e, ao final, serão contabilizados somente os pontos das tarefas realmente concluídas.

A Velocity será utilizada para acompanhar a capacidade da equipe e auxiliar no planejamento dos próximos Sprints. Como a equipe ainda está iniciando o projeto, os primeiros Sprints serão utilizados para estabelecer uma média de referência.

# 7.2 KPIs & Burndown

<!-- Quais métricas o time vai acompanhar -->

| KPI | Meta | Como medir |
|---|---|---|
| Story Points concluídos | Concluir pelo menos 80% dos SP planejados por Sprint | Comparar os SP planejados com os SP concluídos no GitHub |
| Tarefas concluídas | Concluir as tarefas prioritárias de cada Sprint | Acompanhar o status das Issues/Projects no GitHub |
| Cumprimento do Sprint | Finalizar as tarefas dentro do período planejado | Comparar as datas planejadas e realizadas |
| Bugs encontrados | Manter a quantidade de bugs baixa e resolver os críticos antes da entrega | Registrar e acompanhar Issues de bugs no GitHub |
| Pull Requests concluídos | Revisar e integrar as alterações da equipe | Contabilizar os Pull Requests realizados e aprovados |

## Mini-Burndown da Aula

<!-- Preencher após a aula: horas planejadas x horas restantes ao longo do tempo -->

O **Burndown Chart** será utilizado para acompanhar a quantidade de trabalho restante durante o Sprint.

No início do Sprint, será registrada a quantidade total de horas ou Story Points planejados. Ao longo do desenvolvimento, a equipe atualizará a quantidade de trabalho restante conforme as tarefas forem concluídas.

> Os valores abaixo são apenas um exemplo de preenchimento. Devem ser substituídos pelos dados reais da equipe caso a atividade exija o burndown real.

| Momento | Trabalho planejado/restante |
|---|---:|
| Início do Sprint | 40 SP |
| Após 25% do Sprint | 30 SP |
| Após 50% do Sprint | 20 SP |
| Após 75% do Sprint | 10 SP |
| Final do Sprint | 0 SP |

O objetivo é que a quantidade de trabalho restante diminua progressivamente até chegar a **0 no final do Sprint**.
